## Why

Where somebody is was a free-text field of the directory profile alone, governed by the profile's details visibility. Somebody without a directory profile could not say where they are, and somebody with one could not show it in the member lists of the channels they share. Typing it is also the only way to set it, which goes stale for people who move between towns.

## What Changes

- **One location per account**, shown wherever the person is: their directory profile and the member lists they appear in. The directory profile's own `location` is retired and existing values are moved to the account at a visibility no looser than the profile's details had.
- **Two modes.** "Set it myself" (free text, at most 80 characters) or "Detect it automatically": the browser's Geolocation API, asked once in settings, sends a position to this server, which names the nearest town from a bundled GeoNames list and stores only the town. Refreshed every few hours while the application is used, only where permission already stands; never prompts. Where detection is refused or unavailable (the Linux desktop webview), the client says so and offers typing.
- **Visibility: public / members / hidden**, defaulting to hidden, the directory's three choices and wording. One SQL function decides it for every query that returns a person; a directory profile passes its details rank as a ceiling.

**Out of scope:** sending locations to other servers. Federation carries no profile payloads today; 'public' is defined to include remote viewers so that whatever carries one later asks the same function at the anonymous rank.

## Capabilities

### Modified Capabilities

- `messaging/realtime`: a new requirement, Location.
- `directory/profiles`: Developer profiles show the account location instead of holding one.

## Impact

- **API:** `GET/PUT /api/me/location`, `POST /api/me/location/detect`; `location` on room members; `location` no longer accepted or exported in the directory profile document, read-only `location` on the owner's profile response.
- **Schema:** migration 000443 — `user_locations` (accounts backup part), `person_location()`, data moved from and column dropped on `directory_profiles`.
- **Data:** `server/internal/places/places.tsv.gz`, GeoNames cities15000 (CC BY 4.0), regenerated by `go generate` and committed; attribution in `NOTICE` and the hosting guide.
